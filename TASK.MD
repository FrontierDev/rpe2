## Goal
Add a read-only character-facing Achievements view to the existing Profile window using activated dataset definitions plus Profile state.

Depends on: #2, #3, #4

## Primary files
- `client/character/profile/page_ProfileAchievements.lua` **new**
- `client/character/profile/window_Profile.lua`
- `RPEngine_Dev.toc`

## Window integration
Add an `Achievements` tab to the existing `UI.Window` tabs list and wire it into instance state and `RefreshTab()` exactly like Equipment, Spellbook, Traits and Skills.

Do not create a second Profile window.

## Data sources
Definitions:
```lua
Registry:GetActivatedDatasets()
```
Progress:
```lua
Profile.ListAchievementStates()
```
Compose refs as `datasetId:achievementId`.

## UI behavior
Display all Achievements from activated datasets. Recommended structure:
- left filter/navigation pane;
- `All` category;
- unique Achievement tags as optional dynamic filters;
- scrollable Achievement entries.

Each entry should show:
- icon;
- name;
- description;
- complete/incomplete appearance;
- completion date when `completedAt` exists;
- criterion progress where applicable (`current` from Profile state, default 0; `goal` from definition).

Visual completion is determined only by `completedAt` in Phase 1. Viewing the page must never calculate or mutate progression.

## Empty/error states
Handle safely:
- no active datasets;
- no Achievements in active datasets;
- definition without Profile state;
- stale Profile state whose definition is inactive/missing.

## Acceptance criteria
- [ ] Tab opens and refreshes on show.
- [ ] Newly activated dataset Achievements appear.
- [ ] Manually seeded Profile state displays progress/completion correctly.
- [ ] Missing/stale state never throws.
- [ ] No automatic progress is generated by viewing the page.

## Coding-agent instructions
Use existing RPE UI abstractions and Profile window patterns. Keep the page read-only and avoid adding Achievement runtime logic.
